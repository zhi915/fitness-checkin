## 桌面启动快捷方式（服务进程）
- 需求：在桌面放一个启动本地服务器的快捷方式，双击即用、手机同 WiFi 可连。
- 限制：沙箱禁用 WScript.Shell COM，无法用 New-Object -ComObject 生成 .lnk。
- 方案：① 建 ASCII junction `C:\fitnessapp` → `E:\work buddy\健身app`（8.3 短路径在本机被禁用，改用 junction）；② 桌面生成 `健身打卡服务器.bat`，内容为 ASCII：`start /min python -m http.server 8000 --bind 0.0.0.0 --directory C:\fitnessapp`，避免中文路径在 cmd 下乱码。
- 注意：.bat 依赖 WorkBuddy 的 managed python 路径；python 窗口最小化运行，关闭窗口即停服务；端口 8000 占用时需先关旧窗口。
- 验证：按相同参数启动后 localhost 与 192.168.1.105 均 200，页面标题正确。
- 排错（17:42）：用户双击 .bat(8000) 后手机无法打开链接。诊断：8000 端口上挤了多个 python http.server 进程（沙箱残留 + 双击起的 + 我后台起的），抢同一端口导致连接时好时坏；且 192.168.1.105:8000 实测得 000。改端口到 **8080** 重新起（仅 1 个监听、localhost 与 lan 均 200、标题正确）；桌面的 .bat 已同步改为 8080。手机访问地址变更为 **http://192.168.1.105:8080**。提醒用户：下次双击 .bat 前先关掉之前的黑色 python 窗口；IP 可能因 DHCP 变化，变了告诉我或重查。

## 加用户名/密码登录（前端多账户）+ 部署到 GitHub Pages
- 需求：把 App 改成「用户名密码登录、不同用户各自数据」，并部署到 GitHub Pages。
- 关键约束：GitHub Pages 纯静态、无服务器/数据库 → 只能做**前端多账户**（账号密码存本机浏览器，每用户数据隔离），无法跨设备同步（用户已确认接受此方案；选了「我给推送步骤」而非我代推）。
- 实现（改 3 文件）：
  - 数据层按用户隔离：旧单一 `STORE_KEY` 删除，改为 `fitapp_data_<user>` 每用户一个键；新增 `fitapp_users`（账号表，存 salt+hash）、`fitapp_session`（当前登录）。
  - 鉴权：纯 JS 实现 SHA-256（经典 Parker 算法，已用 abc/空串/hello 标准向量验证通过；H 在函数内部每次重建，避免跨调用污染），密码经 5000 次迭代哈希 + 随机 16 字节 salt；**不依赖 crypto.subtle / HTTPS**，局域网 http 也能用。注册/登录/退出完整流程：boot() 检查 session → 无则显示登录页，有则 enterApp；顶栏显示用户名+退出按钮。
  - UI：新增 `#authScreen` 登录/注册页（登录/注册切换 tab），`#app` 默认 `display:none` 防止未登录闪现；header 加用户名与退出；对应 CSS 已加。
  - 旧版单一用户的 `fitness_checkin_v1` 数据不会被自动迁移（多账户后按账号重新积累，已向用户说明）。
- 文件新增：`.nojekyll`（避免 GitHub Pages 用 Jekyll 处理）、`部署到GitHub-Pages.md`（建仓库/推送/开启 Pages 步骤 + 命令）。
- 验证：node --check 通过；重启 8080 服务后 index/appjs/css 均 200，新文件含 authScreen/storeKeyFor；SHA-256 标准向量 OK。本地预览地址仍为 http://192.168.1.105:8080。
